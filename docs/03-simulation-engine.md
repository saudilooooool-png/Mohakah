# 03 — محرك المحاكاة

## المبدأ

> **الذكاء الاصطناعي يدير الحوار والتفاعل، والقواعد تحكم النتائج.**

لا يكفي أن نطلب من نموذج لغوي أن يتظاهر بأنه مدير. لو اخترع النموذج الأرقام لأصبحت التجربة لعبة تمثيل، والتقييم غير عادل وغير قابل للتحقق. لذلك قُسم النظام إلى طبقتين:

| الطبقة | المسؤول | أمثلة |
| --- | --- | --- |
| **الحقائق والنتائج** | المحرك (كود حتمي) | النقد، الإيرادات، العملاء، الجودة، الرضا، الثقة، ما أُطلق ومتى |
| **التعبير والحوار** | وكلاء الذكاء الاصطناعي (لاحقًا) | صياغة رسالة المدير، اعتراض المالية في الاجتماع، رد العميل الغاضب |

الوكيل يقرأ حالة المحرك (مثلًا: ثقة خالد بك 48، والتحليل تأخر) ويصوغ ردًا مناسبًا، لكنه **لا يكتب في الحالة إلا عبر قرارات المحرك المسموح بها**.

## المكونات الستة

```
data/companies/*.json ──► الحالة (state)
data/scenarios/*.json ──► محرك الأحداث ──► صندوق العمل (inbox)
                                            │
                     المتدرب: respond() / submitDeliverable()
                                            │
                          محرك القرارات (effects) ──► الحالة
                                            │
endDay(): المهلات ← الآثار المؤجلة ← خارطة الطريق ← المحرك الاقتصادي ← لقطة يومية
                                            │
                              التقييم (evaluation) ◄── سجل الأدلة
```

| # | المكون | الملف | الدور |
| --- | --- | --- | --- |
| 1 | قاعدة بيانات الشركة | `data/companies/nova-tech.json` | الموظفون، العملاء، المنتجات، الميزانيات |
| 2 | محرك الأحداث | `src/engine/simulation.js` | أحداث مجدولة + أحداث عشوائية مشروطة + أحداث تولّدها القرارات |
| 3 | محرك القرارات | `src/engine/effects.js` | لغة "آثار" صريحة لكل خيار |
| 4 | الوكلاء الذكيون | (المرحلة التالية) | الحوار فوق الحالة |
| 5 | محرك النتائج | `src/engine/economy.js` | معادلات المال والعملاء والدعم والفريق |
| 6 | نظام التقييم | `src/engine/evaluation.js`، `deliverables.js` | درجات مرتبطة بأدلة |

## دورة اليوم

1. **بداية اليوم:** تُطلق الأحداث المجدولة لهذا اليوم، والأحداث التي جدولتها قرارات سابقة، وربما حدث عشوائي (احتمال 30%).
2. **أثناء اليوم:** يعالج المتدرب صندوق العمل بأي ترتيب: يختار من خيارات مسموحة مع تبرير مكتوب، أو يسلّم مستندًا.
3. **نهاية اليوم (`endDay`):**
   - كل بند فات موعده دون تصرف يُغلق كـ"منتهٍ"، وتُطبق عواقب تجاهله (`onExpire`).
   - تُطبق الآثار المؤجلة المستحقة (مثل: "استقالت نورة" بعد 4 أيام من تجاهل إرهاقها).
   - يتقدم فريق التطوير في خارطة الطريق. عند اكتمال بند يُطلق وتُطبق آثاره (`onShip`).
   - تعمل الشركة يومًا كاملًا (المحرك الاقتصادي).
   - تُحفظ لقطة من المؤشرات في `history`.

## لغة الآثار

كل خيار وحدث يغيّر العالم عبر عمليات مكتوبة في بيانات السيناريو، ما يجعل كل نتيجة قابلة للتتبع:

```json
{ "op": "accountHealth", "id": "ufuq", "value": 12 }
{ "op": "trust", "who": "cpo", "value": 5 }
{ "op": "roadmapAdd", "item": { "id": "reports_fix", "effort": 22, "onShip": [ ... ] } }
{ "op": "schedule", "inDays": 4, "note": "استقالت نورة", "effects": [ ... ] }
{ "op": "flag", "name": "promised_ufuq" }
```

العمليات المتاحة: `add`، `multiply`، `set`، `trust`، `accountHealth`، `accountMrr`، `loseAccount`، `competitorPrice`، `roadmapAdd`، `roadmapRemove`، `flag`، `spawn`، `schedule`، `log`.

الأحداث يمكن أن تكون مشروطة (`condition`) بحالة الشركة. مثال: حدث "مرّ موعد الإصلاح" لا يظهر إلا إذا وعدت العميل (`flags.promised_ufuq`) ولم يُطلق الإصلاح (`flags.reports_fixed`). **هكذا تترابط المهام:** وعد اليوم 1 يعود في اليوم 11.

## المعادلات الاقتصادية (يوميًا)

| الكمية | المعادلة |
| --- | --- |
| النقد | `cash += MRR/30 − (الرواتب + البنية + التسويق)/30` |
| الرضا المستهدف | `0.65 × الجودة + 0.35 × (100 − min(100, 1.2 × التذاكر))` |
| رضا العملاء | يقترب من المستهدف بنسبة 5% يوميًا (2% للحسابات الكبرى) |
| الإلغاء الشهري | `1% + max(0, 60 − الرضا)/100 × 15%` |
| العملاء الجدد شهريًا | `(ميزانية التسويق / CAC) × (أرخص منافس / سعرنا)^1.5 × (الجودة/70) × (0.5 + العلامة/100) + نمو عضوي` |
| خسارة حساب استراتيجي | إذا الرضا < 28: احتمال يومي `(28 − الرضا)/28 × 12%` |
| تذاكر الدعم | `+ العملاء/45 + (100 − الجودة)/25 − سعة الدعم` |
| تقدم التطوير | `سعة الفريق × (الروح المعنوية / 70)` نقطة يوميًا |

الإلغاء والاستحواذ يُحسبان بمراكم كسري حتمي، لا بالقرعة، كي لا يُعاقب متدرب بسبب الحظ. العشوائية محصورة في **أي الأحداث تظهر** و**خسارة الحسابات الكبرى عند الخطر**.

## الحتمية والعدالة

- **نفس البذرة = نفس العالم.** مولّد عشوائي حتمي (`rng.js`) بتيارين منفصلين: تيار الأحداث وتيار العالم.
- يستهلك تيار الأحداث عددًا ثابتًا من الأرقام كل يوم مهما فعل المتدرب، فتبقى الأحداث العشوائية متطابقة قدر الإمكان بين عالم المتدرب وعالم "خط الأساس".
- هذا يسمح بمقارنة متدربين مختلفين على العالم نفسه، وبإقامة مسابقات بين فرق على البذرة نفسها.

## أين يدخل الذكاء الاصطناعي في المرحلة التالية

| الاستخدام | المدخلات من المحرك | المخرجات المسموح بها |
| --- | --- | --- |
| صياغة الرسائل والاجتماعات | الحدث، الشخصية، الثقة، السجل | نص فقط |
| اجتماع حواري (مثل اليوم 5) | الاعتراضات المحددة في السيناريو، وردود المتدرب | تصنيف الرد إلى أحد خيارات الحدث + نص الرد |
| تقييم المستندات | المعيار (rubric) ونص المتدرب | درجة لكل قسم + اقتباس الدليل، مع مراجعة بشرية لعينة |
| توليد أحداث جديدة | قوالب أحداث + حالة الشركة | حدث بصيغة السيناريو يمر بالتحقق قبل دخوله |

**تكلفة الذكاء الاصطناعي:** نموذج صغير وسريع للرسائل الروتينية، ونموذج أقوى للاجتماعات وتقييم المستندات فقط.
